# CPL 全頭評価：承認用実装案（2026-09-24）

状態：0022の設計承認済み。開発実装中。`index.html`にはローカル用入口、`all-runner.html` / `all-runner.js` / `all-runner-core.js` / `all-runner.css`には独立した全頭評価画面を追加した。`app.js` / `styles.css` / 本番DB / GitHub Pagesは未変更。独立した開発DBでSQL検証済み。実機Safariと開発DBへ接続したブラウザー操作は未了。

## 判断と結果の境界

1. 「初回評価を確定」成功時、`confirm_race_evaluation`がレースとrevision 1を同時保存する。これが初回判断。
2. 確定後も「人気・結果を見る」までは修正可能。保存ごとに全頭の完全スナップショットと`pre_review`を残す。
3. 「人気・結果を入力」ボタンを押すと、**画面を表示する前に** `begin_result_review` を呼び、サーバー時刻 `result_review_started_at` を一度だけ記録する。RPCが失敗したら結果画面へ進めない。
4. 以後は結果が未入力・未保存でも修正は必ず `post_review`。戻る、再読込、別端末、下書き削除では境界は戻らない。
5. アプリ外で先に結果を見た事実まではシステムから証明できない。CPL内の「事前」は「CPLの結果画面を初めて開く前」という保守的な定義とし、実機UIに明記する。

初回判断は常にrevision 1、結果前最新版は `pre_review` の最大revision、現在最新版は `current_revision_no` を参照。結果を表示した後の修正を事前判断成績へ混ぜない。**好走率は `result_status='official'` のレースだけ**を母集団とし、全指標に分子・分母を併記する。不成立は評価・修正履歴に残すが好走率には入れない。注目馬選択率は予想の的中指標ではなく評価行動の指標なので、評価完了済みなら結果不成立でも分母に含める。

## 取消と競走中止

`races.field_size` は確定した**馬番の最大値**、すなわち出馬表で採番された1〜N頭分の枠として扱う。取消で馬番に欠番ができても、行を詰め直さない。

| 状態 | 評価画面 | 結果保存 | 人気 | 3着以内率の分母 | 分子 |
|---|---|---|---|---|---|
| 通常出走 | 必須評価 | `placed` または `finished_other` | 必須 | 算入 | 公式着順1〜3着（同着全頭） |
| 出走取消 | 取消確定前に評価済みなら初回記録を残す。確定前に取消なら `entry_status=scratched` で必須評価を免除 | `scratched` | NULL | 全指標から除外 | 0 |
| 競走中止 | 必須評価 | `dnf` | 必須 | 算入 | 0 |

取消が初回確定**後**に判明した場合、revision 1の馬体・選択履歴は保存したまま、結果行だけ `scratched` とする。これにより当時の判断を失わず、適性馬・注目馬・非選択馬・馬体条件別好走率の分母から当該馬を除く。注目馬選択率の分母は全頭評価を完了したレース数、分子は注目馬を選んだレース数なので、後から注目馬が取消になっても「選んだ事実」は残す。取消を除いた注目馬の好走率は、その馬を除外する。

競走中止は出走済みなので人気必須。選ばれた馬なら適性馬／注目馬の分母に含むが分子には入らない。非選択なら非選択馬の分母に含む。後から映像を見て馬体を修正しても初回の判定は変わらない。

取消前に人気を確認できないのは自然。取消馬のみNULLを許す。全出走馬の人気は1〜出走頭数の重複なし。競走中止と3着圏外の両方を `finish_position=NULL` とし、`outcome_status`で区別する。

## 同着とレース不成立

`race_runner_outcomes.finish_position` は各馬の**公式着順**1・2・3を保存し、複数馬の同一順位を許す。公式に3着以内の馬は全頭を好走として数えるため、3着同着では好走馬が4頭以上になり得る。1着同着の `1・1・3` のように欠けた順位を勝手に補完しない。馬券の払戻し上の扱いから着順を推測しない。3頭の完走を保存条件にせず、公式に確定した結果であれば3着以内が3頭未満でも入力可とする。データ構造は4テーブルのまま、順位の一意制約と「3頭必須」検証だけを撤去する。

レース全体が公式に不成立なら `race_evaluations.result_status='void'`、個々の結果行は**0件**。確定済みの評価・事前／事後の完全スナップショットと `result_review_started_at` は維持する。公式結果から不成立への訂正時は結果行だけ原子的に消し、評価は消さない。`official` のときだけ馬ごとの人気・着順を保存する。公式結果を再登録する場合もレビュー開始時刻を巻き戻さない。好走率の集計は必ずレース単位の `result_status='official'` と出走馬条件で絞り、結果行がない不成立レースのゼロ件を「0着圏内」と取り違えない。JRA公表の不成立を確認して選択し、単に未入力や遅延という理由で不成立にしない。

## 片手で操作する画面

共通：CPLの黒〜濃緑、1画面1判断、操作領域44px以上、固定的な下部アクション。馬名入力なし。横スクロールの馬番チップと単頭フォームにする（18頭分の縦長フォームを一度に出さない）。

### 1 レース情報

現行の `COURSE_DISTANCE`、競走条件、日付、競馬場、頭数1〜18、馬番最大Nを使用。入力後 `1〜N番の評価を開始`。頭数を変更する場合、高い馬番に既存下書きがあれば必ず確認。

### 2 馬番ごとの評価

上部は `中山 芝 2000m 内回り｜4/16頭 入力済み`。その下に1〜Nの横スクロールチップ（未入力：灰／必須完了：緑／取消：斜線／適性馬：金枠／注目：星）。タップでどの馬番にも移動でき、パドック周回順を強制しない。

中央は「7番馬」の単頭カード：胸前、トモ、ハリ、歩様、前後バランス、膁部のくびれをマスターのチップで選択。イレ込み・発汗・早歩きは控えめな任意欄に置き、未入力をNULL（問題なし）として扱う。「出走取消」ボタンで、公式取消を確認した馬だけ必須評価を免除。取消操作は確認ダイアログを出す。

下部：`前の馬番`／`次の未入力`／`馬番一覧`。入力済み馬へ戻って変更可能。各タップ後にユーザー別draftへ保存。

### 3 適性馬選択

必須評価が全て終わった時点で開く。馬番の複数選択と `適性馬なし` は排他的。未評価・取消馬を候補に出さない。選択した馬体条件の自動判定は行わない。

### 4 注目の1頭

適性馬だけから最大1頭。`注目馬なし` を常に表示。適性馬なしなら注目馬なしに固定し、下書きにも明示する。

### 5 初回判断の確認

レース情報／入力済み頭数／取消頭数／適性馬番一覧／注目馬番を簡潔に確認。`初回判断として確定` を押すとRPCの結果が返るまで二重送信を防止。成功後にだけ入力draftを削除。失敗時はdraftを保持。確定後の修正には必ず新revisionを作る。

### 6 人気・結果

入口 `人気・結果の確認を開始` で `begin_result_review` を先にawait。通信失敗時は画面を開かず、時刻は巻き戻せない旨を確認文に表示。

画面冒頭で `公式結果`／`レース不成立` を選ぶ。不成立なら事実確認のダイアログを経て `save_race_outcomes(raceId,'void')` を呼ぶ。人気・着順入力は要求せず、保存した評価・修正履歴はそのまま。レース詳細に「不成立・好走率の集計対象外」を表示する。

公式結果では馬番順のコンパクトな人気入力カードと `入力済み / 出走馬数` を表示。取消は `出走取消`＋人気入力欄を無効化。中止は `競走中止` とし人気を入力する。次に**公式着順ごと**の1着／2着／3着グループへ馬番を複数選べるようにする。`同着の馬を追加` を各グループ内に置き、選択馬は同じ順位のチップとして表示。1頭を二つの順位へ重複登録しない。公式に欠番の順位（例：1着2頭なら2着なし）は空欄として確定できる。全出走馬を `placed`／`finished_other`／`dnf`／`scratched` のいずれかにし、公式結果の馬番と照合してから保存する。下部固定アクションに `1着: 2頭・2着: 0頭・3着: 1頭` の要約を置き、3頭を超える好走馬も隠さず表示する。入力途中の端末別結果draftは保存成功まで保持する。

### 7 照合・修正

レース詳細に `初回判断`／`結果前最新版`／`現在最新版` の切替と、`結果確認後の修正を含む` 警告を表示。修正は最新revisionを全頭分コピーした編集画面で行い、保存時には前revision番号を送る。別端末で先に更新された場合は `STALE_REVISION` を表示し、再読込してから再編集する。初回判断を直接編集する導線は作らない。

## 下書き・閲覧中断

- 現行 `CPL_V1_INPUT_DRAFT_<userId>` version 2には触れない。新方式は別キー `CPL_V2_ALL_RUNNER_DRAFT_<userId>` version 3（結果入力は `raceId` を末尾に持つ別キー）。
- draftにはレース情報、1〜Nの馬番キー付き評価、現在馬番、ステップ、適性馬、注目馬、取消状態、スクロール／操作位置を入れる。
- `input` / `change` に加え `visibilitychange(hidden)` / `pagehide` / `beforeunload` で保存。`TOKEN_REFRESHED` で画面を初期化しない現行動作を維持する。
- 結果確認開始時刻と確定済みrevisionはDBが正。localStorageで巻き戻さない。別端末で結果確認が始まった場合はDB状態を再取得して事前修正画面を閉じる。
- 取消前にすでに入力済みの値をどう残すかは、未確定draftでは確認を出し、初回確定後は履歴を維持する。

## 今回の限界と承認前確認

`races` は既存の最大18頭モデル。未確認の公式順位・レース状態を推測で補完せず、公式確認前は結果を未保存とする。将来のコース別項目非表示は項目定義と表示条件を分離する拡張余地だけ残し、東京芝1600mの膁部入力は隠さない。後膝項目、適性自動判定、安田記念の暫定仮説ルール化は行わない。

実装時には旧方式の「結果確認済み入力」から、先に評価する正式フローへ切り替える。migration単独を本番へ適用しても旧Webは従来通り動作する。新UIとbackup version 6は別工程で実装し、旧バックアップは読み替えず保持する。
