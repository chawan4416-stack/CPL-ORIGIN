# CPL Ver1.0 研究体系・Architecture Book追補

2026-09-27／CPL-DEV。Project Book相当の`CPL_SPEC.md`研究憲章を実装する。正式公開前の開発仕様。

## DBとmigration

- 0001〜0021は変更しない。0022原本は開発bundle由来、CPL-DEVの適用SQLとMD5 `7a74e03f999a6f476dc53c27647568ac`で一致。
- DEV専用`cpl_dev_only_disposable_test_gate`は開発テストのゲートで、アプリ共通migrationには含めない。
- 0023は`SUITABILITY`マスター、`suitability_observations`、`condition_observations`、所有者別SELECT RLS、認証ユーザーだけに絞ったGRANT・RPCを追加。旧βは維持。
- 0024は適性の公式1着必須と、状態記録内の同一レース人気重複を防ぐ。2着・3着の同着や公式着順の欠番は許容する。
- 0025は適性の馬番入力を公式人気へ置換。旧行の馬番は人気へ推定変換せず保存し、UUID識別子と人気の一意制約を追加する。過去の馬番付き行は再保存時に公式人気の入力を要する。適性の新行には馬番がないため、同一馬の研究横断照合は利用できない。
- 新書込RPCは共有レースを同一ユーザー・日付・競馬場・レース番号で再利用する。既存ヘッダと芝ダート・距離・形態・馬場・頭数・クラスが食い違えば拒否する。別研究の観察を上書きしない。
- 適性の同着は同順位を複数馬へ許し、人気をレース内で一意にする。胸前の厚−／厚は元データで区別する。
- 状態は結果確定後の登録だけ。結果`placed`は人気と1〜3着、`finished_other`と`dnf`は人気と着順なし、`scratched`は人気・着順なし。未選択状態は検査陰性ではなく記録対象外。

## 画面・集計

`research.html`はCPL-DEV専用設定とGoogleログインを使う。適性画面の1〜3着切替はローカル状態を保持し、ユーザー別`localStorage`へ自動保存する。状態は目立った項目とレース・結果を一画面で登録する。

2026-09-28 Focus Design追補：適性入力の着順は切替タブを唯一の入力元とする。各タブの人気・胸前・トモ・ハリを保持し、選択中の着順で同着馬を追加する。RPCへ送る`finish_position`はタブに対応する内部値を使用する。レース必須項目が揃えば要約表示へ畳み、「変更」で再展開できる。展開状態もユーザー別下書きに保存する。ログアウトは記録画面へ移し、認証機能は維持する。DB・RPC・集計・状態研究はこのUI改修では変更しない。

適性集計は24／18セルの件数・割合・母数、セル別ハリ内訳を返す。分母はその条件で記録した好走馬。状態は選んだ状態ごとの記録対象内の1〜3着・着外・中止・取消を返す。チャカつきは1600m以下と1800m以上を追加表示し、中間距離はどちらにも含めない。これらは因果・全出走馬好走率を表さない。

## 権限・運用

新テーブルは`authenticated`のSELECTのみ、書込は所有者・マスターを検証するRPC経由。`anon`に新テーブル・RPC権限なし。旧βのRLS・RPC・履歴を維持する。バックアップv8は新旧研究テーブル（適性UUID・人気を含む）とマスター・競馬場研究資料を含み、CPL-DEV以外への復元を拒否する。旧v5定期ジョブは移行判定まで継続。

競馬場研究の基礎設計書にある胸前・トモ旧区分と前後バランス・歩様は、当時の**コース構造仮説**として保存する。新しい実走入力の分類に読み替えず、検証時に仮説版と観察版を並べる。
分類の対応方針は[`COURSE_RESEARCH_TAXONOMY.md`](COURSE_RESEARCH_TAXONOMY.md)に分離する。
